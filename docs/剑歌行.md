# 剑歌行 · Swordsong

水墨仙侠御剑音游，竖屏为主，横屏也能玩。题眼是“一剑一音，万剑成歌”。目标平台：手机和 PC。
在线页面：https://claude.ai/artifact/Tdb4nLxuAAaQvCoMQ9oVWH
- 第二版（2026-11-15）：改成音游，并去掉所有文字引导。
- 第三版（2026-11-15）：一笔划过即可连斩；支持多指和键鼠。
- 第四版（2026-11-15）：配乐换成现成的古风曲子（录音），判定按每首曲子自己的速度对齐。
- 第五版（2026-11-15）：修好游戏中闪黑框的问题；终章 Boss 从鲲换成中国龙（鲲鹏已经用在《扶摇·九万里》里），章名改为「龙渊」。

- 包里没用上的：《故敌愁》（95 BPM，实际是三拍子，和四拍的谱面对不上）、《画桥雨下》（速度不稳）。《姽婳剑歌》速度也不稳，所以只放在不判定的结局。

- 龙吟（src/audio.js 的 longyin）是合成的：低沉的锯齿波从低滑高再落下，两个共振峰从“呜”张到“啊”再收回，下面一层 31 Hz 抖动的噪声当喉音，上面一条三角波当“吟”的泛音，最后进混响。龙出场前 4 小节、Boss 登场、破云而出、衔珠升天时各响一次。

## 玩法
- 每个灵物都是一个音符。朱砂圈向它收缩，收紧的一刻就是它的拍子。每一击会奏出一个筝音（按当前曲子的五声音阶移调），剑在下一个十六分拍飞出。
- 笔的规则（手指、鼠标、按键都一样）：
  - 正好在拍上点中或划过：当场斩，按准度判 绝 / 妙 / 好。
  - 提前碰到：当场印上朱印（木鱼一声、墨点一溅），到它的拍子自动斩落。拍子到时笔还在它身上判「绝」，否则判「妙」。
  - 拍子到时笔停在哪个灵物上，就斩哪个（「绝」）。
  - 一个灵物有几拍（灯笼、圆盘、龙背上的封印、龙珠）：碰到一次，后面几拍都算印上。
- 结果：按住一路乱划也能 0 失误全连，大多是「妙」（准度约 79%，评级「妙」）；要拿「神」得卡准拍子。
- 鬼火是会飞向玩家的音符，没斩掉就掉命（左下五颗玉珠）。玉坠回血；剑魂给“万剑”充能。每 40 连击充一格（最多 3 格），几秒内自动斩落所有音符。

## 操作
- 手机：每根手指各是一支笔，可以双拇指打，各自留墨迹。「万剑」只用右下角的“剑”按钮，不再用双指手势，以免和双拇指冲突。
- PC：鼠标瞄准（准星跟随）；按住左键划，单击按节拍判定。键盘 Z X C V A S D F 中任意一个等于在准星处落笔（osu! 式），按住键移动鼠标就是划。右键或空格放「万剑」；Esc / P 暂停；标题页按 Enter 开始。
- 判定按输入事件本身的时间戳，不等下一帧。另有不显示的自动偏移，只从点击里学习，按玩家习惯的早晚把判定窗口居中，最多 +90 毫秒。

## 无字引导（第一次进入）
全程不出现任何说明文字，玩家逐关自己领会：一个带呼吸圈的符箓 → 三拍三个 → 八分音符一圈 → 按住灯笼，随后它吐出鬼火 → 剑魂（光点飞向“剑”按钮）→ 鱼群。没碰到就一小节后重来；完全不碰屏幕时，会出现一只半透明的手示范一次。教学完成后记入本机，下次直接开打。

## 结构
- 谱面以小节计：0–24 云海（四分音符）→ 24–48 青绿（出现八分，灯笼开始按拍吐火）→ 48–68 灯海（连流）→ 68–72 龙出场 → 72 起 Boss（龙渊）。每段的实际时长取决于该段曲子的速度。
- Boss 一呼一应、以小节为单位：封印小节（第 1/2/3 拍）、鬼火齐射小节（龙张口吐火，龙口不在画面里时改成封印小节）、召唤小节；二阶段打龙珠（三连或四个八分）。打完后黑龙褪去邪气化为金龙，衔珠盘旋升天，然后结算（准度、绝/妙/好/失、评级 神/绝/妙/良/凡）。
- 谱面是“单轨”：任何时刻最多一个音符。脚本里的阵型手工排开；鬼火和 Boss 的音符只放进空着的时刻（留 0.4 秒余量）。

## 终章 Boss：龙（第五版）
- 造型按传统的「九似」：鹿角（每支四个叉）、驼头（高鼻梁，鼻头宽大上翘）、鬼眼（大而凸出，竖瞳）、牛耳、蛇颈、蜃腹（米金色腹甲）、鲤鳞、鹰爪（四肢各五爪）、虎掌。另有：浓眉卷成云纹，上唇卷边，龙须从唇角伸出、顺着身体飘到后面，下巴一把长髯，腮边火焰状的鳍，头后火焰鬃毛顺颈而下，背上一列尖鳍，肘后火焰毛，尾端火焰尾。
- 两种状态：被邪气侵染时是墨色黑龙，鳞缝里有暗红余烬纹在游动，眼睛橙红，鬃毛是朱红到墨色的笔触；被救下后整条变成金龙，龙珠变成白金色。
- 动作：龙头在镜头前画横“8”字，身体沿龙头走过的路线蜿蜒，所以整条龙总在画面里盘绕。每帧按龙头的解析路线细分采样，低帧率时身体也是平滑曲线。“8”字两端转弯半径保持够大，身体是绕过去而不是折过去。开场从云海下破云而出，龙吟一声。
- 打法：一阶段斩龙背上的 6 道封印（只挑当前在画面里的那道发音符）；龙张口吐鬼火。二阶段龙吐出被侵染的龙珠（暗红裂纹的珠子，固定在画面中间、避开顶部 HUD），斩碎之后龙衔珠升天。
- 文案：阶段卡「潜龙勿用 / 或跃在渊」，Boss 登场「积水成渊 / 蛟龙生焉」，二阶段「龙战于野 / 其血玄黄」，结局「飞龙在天 / 利见大人」和「云从龙 / 风从虎」。结算副标题胜利时「飞龙在天 · 云从龙」，在龙渊失败时「龙渊未渡 · 来日再战」。Boss 血条名「龙」。
- 技术：src/dragon.js。一张 96×4 的浮点贴图存脊柱每一节的位置和坐标系（切线、背向、侧向），顶点着色器按它把整条龙弯起来，只要两次绘制：一次实体，一次半透明的毛发和鳍。龙头所有部件在同一个局部坐标系里建模，再整体放大（HS = 1.3）。下颌绕铰链开合（吼叫、吐火时张开），四肢绕肩划动。src/boss.js 负责路线、封印、龙珠和结局。
- 看龙工具：test/dview.js 是单独的看龙页面，可以从侧面、正面、背面、俯视等角度出图。先 `node test/build_view.mjs` 生成 dist/dview.html，再运行 `python3 test/dview.py 输出.png 宽 高 '[["side",{}],["q34",{"jaw":0.5}],["front",{}],["body",{"path":"coil"}]]'`；参数里 freed:1 / cor:0 看金龙。

## 闪黑框（第五版修复）
- 原因：Windows 上的 Chrome / Edge 通过 ANGLE 把 WebGL 翻译成 D3D11，在那里 pow() 的底数为负时得到 NaN（GLSL 规范里负底数的结果本来就是未定义的，别的平台只是碰巧不出事）。剑身的流光和几处菲涅尔边光会算出负底数；NaN 像素经过 Bloom 被抹成一块块黑框，严重时整屏发黑。
- 修复：所有 pow 的底数先截断到非负；法线归一化前加一个极小偏移，避免零向量。后期在 Bloom 之前加了一道“清洗”：把 NaN / 无穷大的像素换成黑色，并把亮度限制在 32 以内。以后哪个着色器再出类似问题，也只会是一个暗点，不会扩散成黑框。
- 测试工具：test/d3dpow.py 在无头浏览器里把 pow 换成 D3D 的行为（负底数返回 NaN），test/nanscan.js 每 5 帧把场景渲染到浮点缓冲里数 NaN 像素。旧版本每一帧都有 NaN，整屏发黑；新版本关掉清洗也是 0 帧 NaN（一到三段和整场龙 Boss 都测过）。

## 技术要点
- 一个 HTML（约 750 KB）加 music/ 下的 5 个 MP3：three.js r170 用 esbuild 打包内联；后期有 Bloom、色调映射、颗粒和墨晕；画面分辨率随帧率自适应。
- 音频引擎（src/audio.js）：一首“歌”是若干分段 `[起始小节, 槽位]`，组成一张速度表。槽位有录音就放录音，没有就退回合成的分段（原来的程序音乐）。BEAT / BAR / STEP 是随速度表更新的活绑定（src/config.js 的 setTempo）。音符时间用 `beatTime(拍号)` 从速度表换算；阵型原本按 120 BPM 设计，生成时按当前速度伸缩运动时间，灵物仍会在自己的拍子上到位。
- 对齐：录音用 AudioBufferSourceNode 在音频时钟上精确起播；循环曲两端各垫一段（循环点落在连续音频里，避免 MP3 边界咔嗒声）。不同浏览器解 MP3 时保留的编码填充不同（Safari 会多留几十毫秒），所以清单里存了一段 0.6 秒的振幅包络“指纹”，页面解码后做互相关，测出偏移并补偿，误差小于 0.5 毫秒。
- 工具：`tools/analyze.py` 分析曲子（librosa 拍点、拟合并细化到约 1 毫秒的速度与相位、重拍相位、五声调、每拍重音、每小节能量、响度）；`tools/build_tracks.py tools/tracks.config.json` 负责剪切、补循环、编码 MP3、做指纹并生成 `src/tracks.js`（清单和署名）。换曲子只要改 tracks.config.json 再跑一遍。
- 检查：网址末尾加 `#audiocheck`，页面左上角会显示每首曲子的解码状态和测得的偏移。
- 输入：src/main.js 里的 ptrDown / ptrMove / ptrUp 管理多支笔，判定在 updateHits / contact / seal。构建：`node build.mjs src/main.js`。

## 可调参数
- src/config.js：PERFECT ±85 毫秒、GREAT ±170 毫秒；圈提前 0.9 秒出现（OPEN）；晚到超过 0.2 秒算失误（LATE）。
- src/main.js：笔的半径为触屏 50 像素、鼠标/按键 40 像素，再加灵物大小；准度里「妙」按 0.75 计。
- src/dragon.js：龙身长 DL = 280、粗细曲线 RAD、龙头放大倍数 HS；src/boss.js：“8”字的幅度（ax / ay）和速度（每秒 0.58 / 0.66 弧度），封印在龙身上的位置 SEAL_U。
- tracks.config.json：每首的起止小节、是否整首循环、移调（keysound 用）、目标响度（target_db）。
- 阵型的音符位置写在 level.js 每行的注释里（以拍计）；新增阵型后可以用 test/chart.mjs 检查有没有同时出现的音符。

## 测试
- 第五版（龙 Boss）：这次的测试容器只有 2 个 CPU 核，无头浏览器软件渲染只有 1–3 帧/秒，“看到就点”的机器人会因为帧太慢而点晚，成绩不能和第四版直接比。所以改用带时间戳的点击机器人（test/bot3.js，像真实触摸事件一样带时间戳）专门打龙 Boss。
  - 最终版本：一阶段 → 二阶段 → 金龙升天 → 结算，全程无报错，0 失误，准度 0.89。之前几次偶尔有 1 个失误，查明是低帧率下鬼火已被斩中、剑还在飞时就先撞到了玩家，帧率正常时不会这样。
  - “不看节拍一路乱划”的机器人打龙 Boss：0 失误，准度 0.81。
  - 从头打满全程（含教学）能一路打到结算，没有报错。
  - 在用户电脑的 Chrome 里打开线上第五版：标题页和第一段开头的剑身流光正常，没有黑框（只看了开头，没打到龙 Boss）。
- 第四版，无头浏览器里配真实曲子打满全程（268 个音符，打败 Boss，结局播放录音）：
  - 按拍点击的机器人：0 失误，224 绝、44 妙，准度 0.959。
  - 不看节拍一路乱划：0 失误，43 绝、225 妙，准度 0.79。
- 录音每次起播都对在节拍网格上（偏差 0 拍）。
- 曲子还没解码完就开始时，会在下一个小节线换成录音。
- 在用户电脑的 Chrome 里打开线上页面：曲子能从 artifact 自带的文件加载并解码，偏移 0 毫秒。
- 真实输入（第三版测得）：
  - 鼠标按住划过 55 个音符，0 失误。
  - Z 键按拍点击，误差在 15 毫秒以内。
  - 两指同时按下得到两支笔，不会误放万剑。
  - 用真实触摸跑通了无字教学，并顺利接上第一段的录音。
- 没在真机上测过：iPhone 的 Safari 偏移、手机内存、音量平衡（录音整体比原来的合成音乐小约 2–5 dB，敲击音相对更突出）都还要实测。龙 Boss 那一段还没在真机上看过。
